# Paying for x402 resources

[x402](https://github.com/coinbase/x402) lets an HTTP server charge per request: it answers `402 Payment Required` with what it accepts, and the client repeats the request with a signed payment. PurseString can pay these for an agent, under the same policy as everything else.

## What happens

The agent calls the `x402_fetch` tool with a URL, its `agent_id`, a `task_id` and a goal.

1. PurseString fetches the URL. A normal answer comes straight back and nothing is paid.
2. On a 402, PurseString reads the server's payment options and keeps the ones it can pay (see below). It picks the cheapest.
3. The exact price becomes a purchase intent for the URL's host, in USD. It goes through the normal rules: allowlist, auto-approve limit, daily budget, approvals, the [kill switch](policies.md#kill-switch-and-loop-detection) and the audit log.
4. If policy approves, PurseString signs a USDC payment authorization (EIP-3009 `transferWithAuthorization`) for exactly that amount to exactly that address, sends the request again with it, and returns the response. If it needs a human, the agent waits with `get_intent_status` and then calls `x402_fetch` again with the same URL and the `intent_id`. PurseString pays only if the server still asks for exactly what was approved.

Once an intent is paid, calling again returns the stored response and pays nothing. Each intent signs at most one authorization. If the server refuses it or the connection drops, a retry sends that same signed authorization again. Its nonce can only settle on chain once, so a retry can't pay twice.

PurseString never sends a blockchain transaction itself: the server's facilitator settles the authorization. The wallet only needs USDC, not gas.

## What it pays

- Scheme `exact`, EVM networks only, USDC only, via EIP-3009. Permit2 and other transfer methods are refused.
- Networks in `x402.networks`. The default is Base Sepolia (`eip155:84532`), a testnet. Add Base (`eip155:8453`) to pay with real USDC.
- Both protocol versions: v2 (`PAYMENT-REQUIRED`, `PAYMENT-SIGNATURE`, `PAYMENT-RESPONSE` headers) and v1 (JSON body, `X-PAYMENT`, `X-PAYMENT-RESPONSE`).
- https URLs only. Redirects are not followed.

USDC is budgeted as USD, so the policy currency must be USD. Prices are counted in whole cents and rounded up: a $0.001 request counts as $0.01 against the budget, while the exact $0.001 is what gets paid.

## Set it up

1. Make a wallet for the agent's spending and fund it with test USDC on Base Sepolia (Circle's faucet: [faucet.circle.com](https://faucet.circle.com)). Use a wallet that holds only what you're willing to let agents spend.
2. Set its private key in `X402_PRIVATE_KEY` (hex). PurseString never logs or stores it.
3. Turn it on in `policies.yaml` and allowlist the hosts the agent may pay:

```yaml
vendors:
  allowlist: ["api.weather.example"]

x402:
  enabled: true
  networks: ["eip155:84532"]      # Base Sepolia. Add "eip155:8453" for Base (real money)
  max_timeout_seconds: 300        # never sign an authorization valid for longer than this
  max_response_bytes: 100000      # longer responses are cut before reaching the agent
  pay_to:                         # optional: the only address a vendor may be paid at
    - vendor: api.weather.example
      address: "0x209693Bc6afc0C5328bA36FaF03C514EF312287C"
```

Without `pay_to`, the address comes from the server's 402 answer, which the agent can't change but the server can. Pinning it means a compromised or look-alike server can't redirect the money.

## Limits

- This is built from the public x402 specs and tested against a stubbed x402 server, with signatures checked by an independent EIP-712 implementation. It hasn't been run against a live facilitator yet.
- If a server holds a signed authorization and refuses the request, it could still settle the authorization before it expires (at most `max_timeout_seconds`). That is how x402 works; PurseString limits it to one authorization per intent, for the approved amount, to the approved address.
- An authorization that expires unpaid can't be re-signed for the same intent. Submit a new one with a new `task_id`.
